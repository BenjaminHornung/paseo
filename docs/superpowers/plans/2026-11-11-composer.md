# Composer implementation plan

**Goal:** Implement the approved harness-independent prediction profile and harness-scoped context picker.

**Architecture:** Extend host daemon configuration and the existing agent/profile interfaces. Keep prediction generation and capability discovery in dedicated server modules, with the composer consuming typed RPCs. Reuse existing settings, autocomplete, attachment and provider patterns.

**Tech stack:** TypeScript, Zod, React Native/Expo, existing provider SDKs, Vitest and browser verification.

**Spec:** `docs/superpowers/2026-11-11-composer-predictions-and-harness-context-design.md`

**Constraints:** Work in the current feature checkout. Preserve unrelated orchestrator and example edits. No deployment, installation, new dependencies or shared-runtime changes. The High-value tests (80/20) policy supersedes blanket TDD requirements. The controller implements sequentially; an independent reviewer checks the final production diff.

## Verified scope and limits

The setting lives under Host settings, beside Agent profiles. Select an existing supported Pi/Claude profile, then enable predictions. It applies to chats from any provider. Tab accepts an editable draft; Escape dismisses it. Nothing is sent automatically.

Codex 0.167.0 was inspected locally. Its `thread/sample` operation requires an existing persisted source thread and inherits that thread's model; it does not provide the independent fresh sampler needed here. The [public sampling implementation](https://github.com/openai/codex/blob/main/codex-rs/app-server/src/thread_sample.rs) confirms the inherited ephemeral fork approach. Codex prediction profiles therefore remain unavailable. Pi/Claude custom replacement commands and nonempty appended launch arguments also remain unavailable, because they can bypass the isolation options; normal agent launches and configuration are preserved.

Catalog entries come from each session, not another harness's installed files. Before a new chat has a native session, the picker can discover skills only. Pi exposes MCP health through its verified built-in `/mcp` status command; it is queried only while idle. A queued/interrupting message is validated when its fresh turn starts. Steering with Pi MCP context while busy returns a retry/queue error. Pi plugins are limited to loaded extension origins exposed by native commands; hooks-only plugins and unsupported connector catalogs are not invented. Unknown Codex thread plugin exclusions suppress that category.

Claude plugin inventory remains unknown until native initialization reports it. Expected unknown/busy categories are omitted during discovery; genuine failures preserve the healthy categories and expose retry. Submission remains strict and returns the actionable pending-inventory error. Archived agents are never resumed for discovery, and changing a draft's provider removes only mismatched context chips. Pi status interception checks the full native message grammar and only info notifications during the owned MCP query. Pi provides no originating-request metadata, so identical status-shaped notifications cannot be perfectly correlated.
